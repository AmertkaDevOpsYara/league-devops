## ۱. بخش لینوکس

### ۱.۱ در لینوکس منظور از Inode چیست و چه داده‌هایی را ذخیره می‌کند؟

1. ساختارهایی که محتوای فایل‌ها (Data) را ذخیره می‌کنند.
2. ساختارهایی که نام فایل و مسیر کامل آن را ذخیره می‌کنند.
3. ساختارهایی که اطلاعات متادیتا مانند مجوزها، مالکیت، زمان‌بندی‌ها و اشاره‌گرهای بلاک‌های داده را ذخیره می‌کنند.
4. فایل‌هایی که فقط در حافظه RAM وجود دارند.

### ۱.۲ کدام فایل اطلاعات کاربران سیستم را نگهداری می‌کند؟
1. فایل etc/hosts/
2. فایل etc/passwd/
3. فایل var/log/syslog/
4. فایل bin/users/

### ۱.۳ چگونه می‌توان فهمید که یک فایل خاص در یک سیستم لینوکس کجا قرار دارد؟
1. با بررسی inode و دنبال کردن مسیرهای mount در proc/ و تحلیل فایل‌سیستم به‌صورت دستی
2. با استفاده از ابزارهای جستجو مانند find، locate یا which برای resolve کردن مسیر فایل
3. با بررسی جدول فرآیندها (process table) و استخراج file descriptor
4. با استفاده از دستوراتی مانند lsblk و df برای map کردن فایل به device block

### ۱.۴ کدام گزینه نادرست است؟
1. در لینوکس، دستور renice برای شروع یک فرآیند با یک اولویت خاص و nice برای تغییر اولویت یک فرآیند موجود استفاده می شود.
2. با کامند netstat -ntplu می توان همه پورت های TCP و UDP را که برای اتصالات listen میکنند را  لیست کرد.
3. با کامند ulimit می توان منابع را برای کاربران و فرآیندهای مختلف در یک سیستم لینوکس مدیریت کرد.
4. اگر برای فایل Sticky Bit تنظیم شده باشد ،‌ تنها Owner میتواند فایل مورد نظر را پاک کند.

## ۲. بخش Containreization
### ۲.۱ هدف اصلی Containerization چیست؟
1. افزایش RAM سیستم
2. اجرای برنامه‌ها در محیط ایزوله
3. افزایش سرعت CPU
4. جایگزینی سیستم‌عامل

### ۲.۲ کدام گزینه نادرست است؟
1. برای Persistent کردن دیتا کانتینر ما از مفهوم  Docker bind mount و Volume Docker و tmpfs Persiste استفاده میکنیم.
2. ما میتوانیم با انجام برخی ترفند ها تعداد کانتینرها را افزایش دهیم ،حتی اگر Swarm Mode فعال نباشد.
3. منظور از Dangling Images در داکر ایمیج‌هایی هست که تگ (Tag) ندارند و توسط هیچ کانتینری استفاده نمی‌شوند. این ایمیج‌ها معمولاً پس از بازسازی (Rebuild) یک Image ایجاد می‌شوند.
4. در Dockerfile، دستور ADD علاوه بر کپی فایل‌ها، از URL و استخراج فایل‌های فشرده نیز پشتیبانی می‌کند؛ اما COPY فقط فایل‌ها و دایرکتوری‌های محلی را به Image کپی می‌کند.

### ۲.۳ کدام گزینه درست میباشد؟
1. ما میتوانیم با کامند docker stop کانتینر را در حالت pause قرار دهیم و هر زمانی که نیاز شد دوباره process متوقف شده را ادامه دهیم
2. یکی از بهترین روش ها برای اینکه ما در محیط پروداکشن مطمئن باشیم کانتینرها در بروزترین حالت ممکن هستند از نظر جنبه های گوناگون از قبیل patch های امنیتی  و … استفاده از تگ latest میباشد.
3. کاربرد فایل dockerignore. برای جلوگیری قرار گرفتن فایل هایی که نیاز نیست در ایمیج باشد میباشد
4. بهترین روش برای افزایش امنیت و کیفیت ایمیج های داکر اینه که ما تعدا لایه های Dockerfile را افزایش دهیم.

### ۲.۴ برای Persist کردن داده‌ها در Docker معمولاً از چه چیزی استفاده می‌شود؟
1. Namespace
2. Dockerfile
3. Volume
4. Registry

## ۴ بخش Monitoring & Logging
### ۴.۱ کدام گزینه نادرست میباشد؟
1. منظور از Monitoring برای تشخیص و پیگیری مشکلات شناخته‌شده است؛ Observability برای کشف و تحلیل مشکلات ناشناخته و رفتارهای پیش‌بینی‌نشده سیستم است.
2. وظیفه Traces برای رهگیری جریان درخواست‌ها بین سرویس‌ها استفاده می‌شود.
3. یکی از ۴ سیگنال طلایی مانیتورینگ Latency میباشد ، یعنی چه مقدار درخواست یا بار روی سیستم وجود دارد.
4. هر ترکیب یکتا از نام Metric و Label ها یک Time Series مستقل است.

### ۴.۲ کدام گزینه درست میباشد؟
1. در سیستم‌های مانیتورینگ، Push و Pull دو رویکرد اصلی برای جمع‌آوری و ارسال متریک‌ها از برنامه‌ها به سامانهٔ نظارتی هستند.
2. در سیستم های مانیتورینگ مانند پرومتئوس ۴ نوع متریک وجود دارد که Summary برای نمایش مختصر لاگ ها میباشد
3. برای اینکه هشدارها را با اهمیت جلوه بدهیم ، باید Alert Fatigue را افزایش دهیم
4. در Observibility واژه های Metrics , Logs , Traces بار یکسان دارند و به جای هم میتوان استفاده کرد

### ۴.۳ در روش RED برای Observability، به ترتیب چه چیزی را اندازه‌گیری می‌کنند؟
1. میزان مصرف منابع سیستم، نرخ اشباع (Saturation) و تعداد خطاهای زیرساخت
2. حجم ترافیک پردازش‌شده، درصد درخواست‌های ناموفق و زمان پاسخ‌دهی درخواست‌ها
3. تعداد کاربران فعال، نرخ رشد ترافیک و زمان در دسترس بودن (Availability)
4. تعداد Span های تولید شده، حجم Log ها و تعداد Trace های ناموفق

### ۴.۴  منظور از Log-based Metrics چیست؟
1. معیارهایی هستند که مستقیماً از مصرف CPU و حافظه سرورها جمع‌آوری می‌شوند.
2. معیارهایی هستند که با شمارش و تجمیع الگوها یا فیلدهای مشخص در لاگ‌ها تولید می‌شوند و می‌توانند بدون افزودن Instrumentation اختصاصی در کد، اطلاعات کاربردی ارائه دهند.
3. معیارهایی هستند که فقط از Trace ها و Span های سیستم‌های Distributed Tracing استخراج می‌شوند.
4. معیارهایی هستند که تنها از طریق تست‌های عملکرد (Performance Tests) قابل تولید هستند.

## ۵ بخش CI/CD
### ۵.۱ کدام گزینه نادرست میباشد؟
1. در Continuous Delivery دیپلوی به طور خودکار انجام میشود و Continuous Deployment دیپلوی به طور دستی انجام میشود.
2. Artifact Promotion یعنی انتقال همان Artifact ساخته‌شده و تست‌شده بین محیط‌های مختلف بدون Build مجدد.
3. هدف Unit Tests در یک پایپ‌لاین CI/CD این هست که بخش‌های کوچک و مستقل کد را بررسی می‌کنند تا خطاها در مراحل اولیه توسعه شناسایی شوند.
4. Ephemeral Build Environment یک محیط موقت است که فقط برای اجرای فرآیند Build ایجاد می‌شود و پس از پایان کار حذف یا نابود می‌شود.

### ۵.۲ کدام گزینه درست میباشد؟
1. وجه شباهت Trunk-Based Development و Gitflow این است که توسعه دهنده ها مستقیم تغییرات را به branch اصلی push میکنند .
2. در TDD اول تست کد را می‌نویسیم، بعد کد را می‌سازیم ، در حالی که در BDD اول رفتار مورد انتظار کاربر را تعریف می‌کنیم، بعد سیستم را می‌سازیم. ( گزینه درست )
3. Approval Stage یک مرحله در Pipeline است که قبل از انجام Deploy روی محیط Stage تست شده باشد.
4. Release Train یک استراتژی انتشار نرم‌افزار است که در آن Release ها منتظر میمانند که همه ویژگی های یه نرم افزار مانند واگن های قطار آماده شود تا به محیط پروداکشن Deploy شوند.

### ۵.۳ کدام‌یک از گزینه‌های زیر مستقیماً به افزایش قابلیت استفاده مجدد (Reusability) و مقیاس‌پذیری (Scalability) در طراحی Pipeline های CI/CD کمک نمی‌کند؟
1. استفاده از Templates و Shared Libraries برای جلوگیری از تکرار منطق Pipeline
2. پارامتری‌سازی Pipeline ها جهت استفاده در پروژه‌ها و محیط‌های مختلف
3. استفاده از Blue-Green Deployment برای کاهش Downtime هنگام انتشار نسخه‌های جدید
4. استفاده از Containerized Build Environment برای ایجاد محیط Build یکپارچه و قابل تکرار

### ۵.۴ تیم توسعه قابلیت جدیدی را به درگاه پرداخت اضافه کرده است و تصمیم دارد پس از اتمام تست‌های نهایی، این قابلیت را در زمان‌بندی مشخص و به‌صورت کنترل‌شده برای مشتریان فعال کند. تیم DevOps برای کاهش ریسک انتشار و امکان بازگشت سریع در صورت بروز مشکل، چه راهکاری را پیشنهاد می‌دهد؟
1. استقرار مستقیم (Direct Deployment) برای همه کاربران به‌صورت همزمان
2. استفاده از Feature Flag برای کنترل زمان فعال‌سازی قابلیت و Canary Deployment برای انتشار تدریجی آن
3. افزایش تعداد سرورهای عملیاتی پیش از انتشار قابلیت
4. انجام مجدد تست‌های واحد (Unit Test) پس از استقرار در محیط تولید

## ۶. بخش Networking
### ۶.۱ کدام گزینه well-known پورت ها را بیان میکند؟
1. 0–1023
2. 1024–49151
3. 49152–65535
4. 1024-2048

### ۶.۲ درباره سه گانه CIA) Confidentiality, Integrity & Availability) کدام تعریف نادرست میباشد.
1. منظور از Confidentiality : ییعنی اطلاعات فقط در اختیار افراد یا سیستم‌های مجاز باشد. مثال، مشاهده رمز جیمیل شما توسط فرد غیرمجاز، نقض محرمانگی اطلاعات است. و یکی از راه های تایید محرمانگی بررسی Hashing میباشد.
2. منظور از Integrity : یعنی اطلاعات درست، کامل و بدون تغییر غیرمجاز باقی بمانند. و یکی از راه های تایید Integrity بررسی Hashing میباشد.
3. منظور از Availability : دسترس‌پذیری یعنی اطلاعات و سیستم‌ها هر زمان که کاربران مجاز به آن‌ها نیاز داشتند، قابل دسترسی باشند. نمونه تهدید برای دسترس‌پذیری حمله DoS و DDoS را میتوان نام برد
4. منظور از Integrity : به معنای حفظ دقت، کامل بودن و صحت اطلاعات است؛ به‌گونه‌ای که داده‌ها بدون مجوز تغییر نکنند یا تخریب نشوند. استفاده از امضای دیجیتال برای درستی یکپارچگی میتواند استفاده شود

### ۶.۳ کدام گزینه نادرست میباشد؟
1. در Data link layer اضافه شدن header و در لایه های 6,5,4,3 اضافه شدن tailer
2. Server farm  مجموعه ای از سرورهای زیادی است که به یکدیگر متصل شده و در یک مرکز فیزیکی قرار دارند .
3. Symmetric Key Encryption : در این روش، یک کلید واحد هم برای رمزگذاری و هم برای رمزگشایی استفاده می‌شود.
4. الگوریتم های RSA , Diffie–Hellman برای رمزگذاری های Asymmetric Key Encryption میتوان به کاربرد

### ۶.۴ کدام گزینه درست میباشد؟
1. Intrusion Prevention System و Intrusion Detection Systems عملکردی ، رفتار و فرایند کاملا یکسان در شبکه دارند.
2. در IP Spoofing، مهاجم آدرس IP مبدأ بسته‌های ارسالی را جعل می‌کند تا بسته‌ها از طرف یک سیستم یا کاربر معتبر به نظر برسند.
3. پروتکل pop3 برای فرستادن ایمیل است و شماره پورت آن 110 میباشد.
4. مدل TCP/IP و OSI از نظر تعداد لایه ها برابر هستند . و در پیاده سازی مدل TCP/IP کارکرد یکسان با OSI دارد.

## ۷. بخش Infrastructure as Code
### ۷.۱ در یک سامانه مالی با ترافیک بالا، هدف این است که نسخه جدید بدون Downtime منتشر شود، در صورت بروز مشکل بتوان در چند ثانیه Rollback کرد و قبل از انتشار کامل، نسخه جدید روی درصد کمی از کاربران واقعی آزمایش شود. کدام استراتژی Deployment مناسب‌تر است؟
1. Recreate Deployment
2. Rolling Deployment
3. Blue-Green Deployment
4. Canary Deployment

### ۷.۲ کدام گزینه نادرست میباشد؟
1. یکی از مهم‌ترین مزایای Stateless Process، که به‌عنوان یکی از اصول کلیدی در ۱۲-Factor Cloud Native Application شناخته می‌شود، مقیاس‌پذیری (Scalability) بهینه‌تر است.
2. منظور از Chaos Engineering بررسی می‌کند سیستم هنگام Failure و شرایط غیرمنتظره چقدر مقاوم است.
3. منظور از Service Mesh یک لایه زیرساختی برای مدیریت ارتباطات بین سرویس‌ها در معماری monolithic است. ( این گزینه درست است)
4. Infrastructure Drift (انحراف زیرساخت) زمانی اتفاق می‌افتد که وضعیت واقعی زیرساخت‌های اجرا شده (Actual State) با وضعیت تعریف‌شده در کد (Desired State) تفاوت پیدا کند.

### ۷.۳ سرویسی داریم که مشتریان به‌صورت روزانه از آن استفاده می‌کنند و حجم داده‌ها به‌طور مداوم در حال تغییر است. هدف این است که در صورت بروز خرابی، بتوانیم داده‌های همان روز را با کمترین زمان بازیابی (RTO) ممکن بازگردانی کنیم. (با فرض اینکه دیتا هر روز به روز پیشین وابسته نیست)
1. یک Full Backup هفتگی و Incremental Backup روزانه
2. گرفتن Full Backup روزانه
3. یک Full Backup هفتگی و Differential Backup روزانه
4. فقط Incremental Backup روزانه بدون Full Backup

### ۷.۴ یک سرویس داریم که:

سرور اصلی از نظر CPU و RAM در وضعیت مناسبی قرار دارد اما فضای Storage آن محدود است.

یک سرور دیگر داریم که فضای Storage فراوانی دارد اما قدرت Compute آن کمتر است.

سرویس به شدت Compute-intensive است و بخش عمده داده‌های آن به صورت Unstructured Data (فایل، تصویر، ویدئو، لاگ و ...) ذخیره می‌شوند.
بهترین راهکار برای حل این چالش چیست؟


1. انتقال کامل سرویس و داده‌ها به سرور دوم
2. افزایش حجم دیسک سرور اصلی و نگهداری همه چیز روی همان سرور
3. جداسازی Compute و Storage؛ اجرای سرویس روی سرور اول و نگهداری داده‌ها روی Storage Server یا Object Storage
4. توزیع تصادفی داده‌ها بین دو سرور

## ۸. بخش Version Control
### ۸.۱ کدام گزینه عملکرد اصلی دستور git stash را به‌درستی توصیف می‌کند؟
1. تغییرات را به صورت دائمی در مخزن ذخیره و Commit می‌کند.
2. تغییرات فعلی را به‌طور موقت ذخیره کرده و Working Directory را به آخرین Commit برمی‌گرداند.
3. تمام Branch های پروژه را حذف می‌کند.
4. تغییرات را مستقیماً به مخزن Remote ارسال می‌کند.

### ۸.۲ هدف اصلی از انجام Squash در Git چیست؟
1. ادغام چند Commit در یک Commit برای داشتن تاریخچه‌ای تمیزتر
2. حذف کامل یک Branch از مخزن
3. بازیابی فایل‌های حذف‌شده از Repository
4. انتقال Commit ها به یک Remote Repository

### ۸.۳ کدام گزینه نادرست میباشد؟
1. در مدل Gitflow توسعه دهنده ها به طور مستقیم روی برنچ main / master تغییرات خود را push میکنند.
2. در مدل Trunk-Based Development  گام تست به شدت اهمیت دارد.
3. در ساختار Monorepo (تک ریپازیتوری) ، میتونیم چندین سرویس داشته باشیم . برخلاف Multirepo که تنها یک ریپازیتوری به ازای هر سرویس باید داشته باشیم.
4. در Git مفهوم  Origin به نام پیش فرض ارائه شده به مخزن Remote اشاره می کند و میتواند نام دیگری داشته باشد.

### ۸.۴ کدام گزینه درست میباشد؟
1. دستور git fetch تغییرات را از مخزن Remote دریافت می‌کند، اما آن‌ها را به‌صورت خودکار با Branch فعلی ادغام نمی‌کند.
2. منظور از Staging Area همان Remote Repository است که Commit ها در آن ذخیره می‌شوند.
3. هدف از Cherry-pick انتقال همه Commit های یک Branch به Branch دیگر.
4. منظور از Detached HEAD یعنی HEAD مستقیماً به یک Commit اشاره می‌کند، نه به یک Branch. در این حالت می‌توانید Commit جدید بسازید، و برای نگهداری تغییرات آن‌ها نیاز به Branch جدید ایجاد نیست.
